# 两轮企划归属与增量事实实验

这是隔离实验，不是生产通知管线。入口不会发送邮件、采集来源或修改生产 state/page。

```powershell
.\.venv\Scripts\python.exe scripts/run-local.py --two-pass-review .herald-work/two-pass-review-20261025
```

仅由 `run-local.py` 读取已有本地配置并注入子进程。实验要求所选模型名称包含 DeepSeek；不输出密钥、环境变量、HTTP 错误正文。请求仅含公开文字、公开链接、IP 提示与公开事实；不含图片。

## 实验设计

从本地已 fetch 的 `origin/page` 读取 2026-10-24、25 日提醒卡片，定位候选及其对应版本的完整 observation。并非按帖子发布时间截取，也不是全部历史候选的召回评估。从空库开始回放 24 日，再把结果用于 25 日，不使用 25 日企划状态推断 24 日。

第一轮提供已有企划的一句语义短语及新帖子，返回多对多来源归属；短语用于检索理解，程序编号用于稳定引用。全部输入帖子必须归属、排除或 pending。第二轮按企划提供旧事实和新帖子，输出带逐字原文证据的事实，程序检查来源、引用、重复键，再计算 before/after。旧事实未被提及不删除。

每个企划每日最多一张变化卡，原帖只作为证据；重复来源版本通过程序门控。额外强制调用一次模型重新处理已有国图事实，检验语义重复，而不只检验来源缓存。

请求与回答、公开数据集、事实目录和报告保存在指定目录。成功回答按完整请求签名缓存，失败不会缓存。重跑从空库重新计算，缓存命中不再消耗模型请求。该缓存只是实验恢复机制，不是生产通知回执。

## 明确边界

- 仅验证公告归属与事实增量。旧日报的日期提醒不纳入新消息数量，也未重编译日期队列。
- 排除纯线上非联动活动是模型范围判断，不能计为去重收益。
- 证据存在不代表语义必然正确；需要人工核对原帖，不能仅凭 JSON 校验宣称可靠。
- 当前事实键和值仍是自由文本。上线前需约束 Activity/Action/属性身份、规范日期与值，并验证同义改写、冲突和取消。
- 单次重复实验不证明长期稳定。还需扩大样本验证错误归属、企划改名、合作方未知、同合作方不同届次。
- 不包含生产发送快照、旧回执迁移、收件人失败恢复以及 pending 全链路接入。这些应在正式实现时单独测试。
- 不自动发布修改，也不会改变远端已经发送的邮件。
