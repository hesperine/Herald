# 千问多帖批处理实测（2026-09-12）

这里的批处理指一次 chat/completions 请求包含多帖，不是供应商异步 Batch API。

使用当前模型配置，显式设置 AI_THINKING=disabled、AI_MAX_TOKENS=8192；thinking 参数的实际语义由服务商决定。同一官方账号的 skland-5960093、skland-5960185 两篇公开正文合在一次初始化请求。未传图片，未发送邮件。

一次请求返回 HTTP 200，覆盖两帖，生成一个 Campaign、两个 Activity，pending=0。耗时54.453秒，输入6915 tokens，输出2330 tokens，无输出截断。原始请求、回答、状态和页面位于忽略目录 `.herald-work/qwen-batch-20260912/`。

正确项：七城市、预约要求、预约具体时间、快闪日期、线上预售具体时间。

未通过的语义质量项：线下和线上满赠被合成一个 Action，并错误归到线上活动，使用线下期限；店铺折扣时分被降成日期；现场售卖明确的日期未填到购买 Action。不能将批处理链路成功等同于提取质量达标。

`src/herald/data/activity-examples.json` 是虚构 Few-shot 教学数据，不是评测数据。当前选第一条，每次随提取请求发送；批处理入口把它包成单来源的 groups 示例，并没有示范真正的多帖整合。后续调试应考虑增加多帖教学覆盖，分别评估分组、召回、时间归属和精度，而不只看 JSON 校验通过。
