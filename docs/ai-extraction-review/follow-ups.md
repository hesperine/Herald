2026-09-12 讨论记录，暂不接入生产。

- 考虑使用成熟的中文轻量 OCR（例如 RapidOCR + ONNX Runtime），在 CPU 上逐图提取文字，保留图片编号、位置和置信度。
- 第一轮 LLM 同时接收正文与按图分组的 OCR 文字，提取现有 Campaign → Activity → Action，并标记需要视觉复核的图片和具体问题。
- 图片无日期是正常情况，不因缺日期就要求视觉模型生成日期。此前商品长图的 URL 测试返回了无依据的日期，不能将接口成功视为提取正确。
- 后续实验比较准确率、漏提率、视觉调用比例、耗时和成本；OCR 证据与正文证据分开保存。

## 当前讨论：有期限的参与事项与条件性结束

已确定保持 Campaign → Activity → Action，Activity 卡片内折叠展示 Action。2026-09-12 已实现 gift/discount 类型、scope/quantity_limit/end_condition/ended 字段、独立日期提醒与卡片内参与事项。OCR 仍未实施。真实模型输出需持续评估。

- 「月行水上」的满赠期限当前在 Action.rules，店铺立减期限在 Activity.related_offers，均为文本，无法自动形成卡片时间及提前一天提醒。
- 有独立有效期的优惠需要结构化表达名称、适用范围、条件、开始和截止时间，并进入统一提醒调度；不能直接作为整个预售的起止时间。
- 明确 Activity、Action 与卡片粒度的职责，避免为展示日期而重复建立活动。
- 区分确定的截止日期与“售完即止”等条件性结束。限量数量本身不等于已知截止时间，也不一定意味着售完即结束。
- 条件性结束不能计算提前一天提醒，不能仅因标记限量就推断售罄。若同时有日期和售完即止，应保留两个结束约束及原文。
