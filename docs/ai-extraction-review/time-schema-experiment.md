# 嵌套时间结构对照实验

实验将第一轮模型输出的互斥字段 `at/start_at/end_at/start_date/end_date` 改成 `start/end` 对象：

```json
{"start":{"date":"2026-09-08","time":"12:00","timezone":"Asia/Shanghai"},"end":null}
```

只有日期时 `time=null`；日期未知时整个对象为 null。不自动补午夜。第一版实验仅处理中国区，timezone 固定 Asia/Shanghai，时刻接受 HH:MM 或 HH:MM:SS。

`scripts/time-schema-experiment.py` 转换实际提取请求的 Schema、Few-shot 时间字段及时间说明，并将模型回答和引文路径转换回现有领域模型。原始 trace 保留模型实际的新结构，state/page 使用原格式。原始模型返回非法时间、混入旧字段会失败，适配器不会从正文补日期。不同批处理组的证据路径独立转换。

通过调试工作器配置 `debug-options.json` 的 `time_schema: "nested"` 启用；默认不启用。正式配置、历史 state、二轮合并 Schema 均不迁移。本次比较的是第一轮时间表达变化；二轮仍接收转换后的原领域格式。

基线 `.herald-work/micro-benchmark/api-20260916-01/`，实验 `.herald-work/micro-benchmark/api-20260916-time-v2/`。固定相同5个测试点、模型、批大小2、关闭思考、输出上限8192，各点单轮。Prompt仅替换时间表述、Few-shot仅转换时间字段和相应证据路径，未修改事实期望。请求长度随Schema改变，不能宣称token数量相同。

日期精度与语义归属分别评估；保住时分不代表日期属于正确事项。单轮改善不能证明稳定性。
